## 控制台是什么

控制台是一个 React 单页应用，编译进 `spinneret-server` 二进制文件里，由服务端在自己 HTTP 监听地址的根路径上
直接提供——没有单独的 Web 服务，没有单独的端口，也没有额外要部署的东西。

| 项目 | 取值 |
| --- | --- |
| 访问地址 | `SPINNERET_HTTP_ADDR` 的根路径（默认 `:8080`） |
| 开关 | `SPINNERET_UI_ENABLED`（默认 `true`） |
| 调用的 API | 与节点调用的是同一套 Connect API，同源 |
| 事件流 | `GET /api/v1/events/stream?tenant=<id>&namespace=<name>` |

如果某些实例只需要对外提供 API，把 `SPINNERET_UI_ENABLED=false` 关掉即可。不像静态资源请求的未知路径会回落到
应用外壳，因此 `/identities/abc123` 这类客户端路由刷新页面后依然可用。

控制台没有任何特权后门：它发出的每一个请求都要经过同样的服务、同样的权限校验和同样的审计日志。API 里做不到的事，
在这里同样做不到。

## 登录

在浏览器中打开服务端地址。未登录的访问者会被重定向到 `/login`，原本想访问的页面会保留在 `redirect` 查询参数里
（`/login?redirect=/identities`）；只接受同源路径，所以这个参数不会被用来把人跳转到站外。

用用户名和密码登录。系统没有自助注册：第一个平台管理员由 `spnr admin init` 创建，之后的用户由持有 `user:write`
的人在[「用户」](#导航地图)页面创建。详见[《租户、用户与令牌》](./11-access-control.md)。

### 会话是什么

| 属性 | 行为 |
| --- | --- |
| Cookie | `spinneret_session`，登录成功后由服务端下发 |
| 有效期 | `SPINNERET_SESSION_TTL`，默认 `12h`，**滑动过期**——每次使用都会续期 |
| 存储 | 在服务端的 Redis/Valkey 中；吊销立即生效 |
| CSRF | 控制台的每个请求都带 `X-Spinneret-CSRF: 1`；用 Cookie 认证的非安全请求缺少它会被拒绝 |
| 当前租户 | 通过 `X-Spinneret-Tenant` 请求头传递；事件流上则用 `tenant` 查询参数 |
| `Secure` 标记 | `SPINNERET_COOKIE_SECURE`——`auto`（默认）、`true` 或 `false` |

`auto` 的含义是：请求走 TLS 到达，或者经由 `SPINNERET_TRUSTED_PROXIES` 中列出的反向代理并带了
`X-Forwarded-Proto: https` 时，Cookie 会被标记为 `Secure`。如果代理不在这个列表里，请显式设置该变量——参见
[《安装与部署》](./02-installation.md)。

会话过期或被吊销后，下一个请求会以 `session_invalid` 失败，控制台会清空本地缓存的数据，并带着当前页面作为
重定向目标把你送回 `/login`。

### 登录失败

登录尝试在两个维度上被限流：

| 维度 | 上限 | 时间窗口 |
| --- | --- | --- |
| 按用户名 | 5 次失败 | 15 分钟 |
| 按客户端 IP | 20 次失败 | 15 分钟 |

任一维度超限都会返回 `login_throttled`，登录表单会显示还要等多久。登录成功会清除该用户名的计数，并归还它在 IP
计数上占用的那一次；同一个 IP 上其他失败记录仍然计在账上。

### 退出登录

右上角的账号菜单里有**退出登录**。它会在服务端结束会话，并丢弃控制台缓存的全部数据。在「个人资料」页面修改密码
会注销你的**其他**会话，当前会话保留。

## 界面外壳

每个已登录页面都渲染在同一层外壳里：左侧是侧边栏，上方是顶栏，中间是页面本身。

### 侧边栏

侧边栏承载导航，分成六个分组：

| 分组 | 页面 |
| --- | --- |
| 概览 | 概览（这个分组标题本身不绘制） |
| 调度 | 身份、身份类型、账号、代理、站点、策略、冷却热力图、熔断器 |
| 配置 | 配置中心、密钥 |
| 可观测性 | 请求明细、风险事件、通知 |
| 访问控制 | 令牌、用户、审计日志 |
| 平台 | 租户 |

还有第七个分组**设置**，它只作为面包屑存在：其下唯一的页面「个人资料」从账号菜单进入。

关于它的行为：

- **没有读权限的入口不会显示。** 每个入口对应一个读权限；当前作用域没有授予时，入口消失；一个分组的入口全部消失后，
  分组本身也不再显示。
- **收起。** 底部的按钮可以把侧边栏收成只剩图标。这个选择保存在当前浏览器的 `spinneret.sidebar.collapsed` 键下，
  刷新后仍然有效。收起状态下，鼠标悬停或键盘聚焦到图标会以气泡提示显示页面名称。
- **顶部的 Logo** 链接到概览页。

### 顶栏

从左到右依次是：面包屑导航、租户切换器、`/`、命名空间切换器、实时更新指示点、语言菜单、主题菜单、账号菜单。

面包屑由当前路由生成：先是导航分组，详情页再加上其父页面，最后是当前页面。在身份详情页上它会是
`调度 › 身份 › 身份 <id>`，中间那一节是回到列表的链接。

浏览器标签页标题取自同一来源，格式为 `<页面> · Spinneret`。详情视图会把页面那部分换成你正在查看的对象的标识或名称
——身份详情页用的是身份 ID，打开某条策略时用的是策略名称。

## 作用域切换器

顶栏里的那一对下拉框——**租户**和**命名空间**——是控制台里最关键的控件。你看到的几乎所有内容都以它们为作用域。

| 切换 | 影响 |
| --- | --- |
| 租户 | 每个请求上的 `X-Spinneret-Tenant` 请求头、命名空间列表、你的有效权限，以及整个可见数据集 |
| 命名空间 | 所有命名空间级请求携带的命名空间：身份、代理、站点、策略、熔断器、配置、密钥、令牌、各类看板以及事件流 |

两者都记在当前浏览器里（`spinneret.tenant`、`spinneret.namespace`）。登录时控制台会恢复你上次的选择；如果那个租户
已经无法访问，就回退到你能访问的第一个租户，命名空间则回退到 `default`，再不行就取该租户的第一个命名空间。

有三点值得记住：

- **缓存也是按作用域分的。** 每个查询的键都包含租户和命名空间，所以切换之后绝不会在新数据加载完之前先给你看上一个
  作用域的行。
- **实时流会重新订阅。** 事件流是按租户和命名空间打开的，切换会触发重连。
- **如果有编辑器存在未保存的更改**，切换不会静悄悄发生：会弹出对话框询问是否放弃，选项是**继续编辑**和**放弃更改**。

有两个页面在没有任何租户访问权限时也能用：**租户**和**个人资料**。完全没有角色绑定的用户在其他页面上会看到
「没有租户访问权限」，并被告知去联系租户所有者或平台管理员；平台管理员看到的则是创建第一个租户的引导。

**注意。** 作用域**不在 URL 里**。你复制出去的链接带着页面和筛选条件，但对方是在他自己的租户和命名空间下打开它的。
记得说明你指的是哪个命名空间。

## 实时更新与提示消息

顶栏里那个彩色小圆点表示当前作用域下 Server-Sent Events 事件流的状态。

| 圆点 | 含义 |
| --- | --- |
| 绿色 | 实时更新已连接 |
| 蓝色，闪动 | 正在连接实时更新 |
| 琥珀色，闪动 | 实时更新正在重连 |
| 灰色 | 实时更新未开启——没有选中租户或命名空间 |

事件流一共传递六类事件。每一类都会在大约半秒内刷新受影响的页面（连续到来的事件会被合并成每个领域一次刷新），
其中两类还会弹出提示消息：

| 事件 | 刷新 | 提示消息 |
| --- | --- | --- |
| `breaker.transition` | 熔断器、看板、站点 | 有——「熔断器打开 / 半开 / 关闭」，站点开关则是「站点已暂停 / 已恢复」 |
| `identity.state` | 身份、账号、冷却热力图、看板 | 无 |
| `proxy.state` | 代理、看板 | 无 |
| `alert` | 通知、看板 | 有，但熔断类和身份过期类告警除外，它们会与上面的事件重复 |
| `config.published` | 配置 | 无 |
| `policy.published` | 策略、熔断器、站点 | 无 |

提示消息出现在右下角，按严重程度着色，带关闭按钮，6 秒后自动消失。它们只是提醒：同样的信息在它指向的页面上都有。
事件流本身在[《可观测性与告警》](./12-observability.md)中详述。

## 语言、主题与账号菜单

**语言。** English 和简体中文。初始语言先看你保存过的选择，再看浏览器语言，最后回落到英文。这个选择保存在当前浏览器的
`spinneret.lang` 键下，同时会设置文档的 `lang` 属性，使读屏软件能正确发音。它是浏览器级别的偏好，不是服务端的账号设置。

**主题。** 浅色、深色或跟随系统。「跟随系统」会跟着操作系统设置实时变化。选择保存在 `spinneret.theme` 下。语言和主题
菜单在登录页上也有，登录之前就能用。

**账号菜单。** 最右侧的圆形按钮显示你姓名的首字母。展开后是你的显示名称、邮箱、平台管理员时显示的**平台管理员**标记、
指向**个人资料**的链接，以及**退出登录**。

**个人资料**页（`/settings/profile`）展示服务端记录的账号信息——用户名、显示名称、邮箱、上次登录、创建时间——你的角色
绑定能访问的租户及其授予你的角色、同样的语言与主题控件，以及修改密码的表单。

## 页面说明卡片

每个页面标题正下方都有一张可折叠的卡片，标题是**本页面的用途**。它不是装饰：它是关于这个页面最短的准确描述，和本套
文档依据的是同一份源码。

每张卡片有三部分：

1. 一段**概要**，说明这个页面控制什么。
2. 三条**通常怎么用**的要点。
3. **什么时候用：** 一个会把你带到这个页面的具体场景。

有明显关联页面的卡片还会在下方列出**相关页面**链接。

点击卡片标题即可折叠。折叠状态按页面分别记在当前浏览器里（`spinneret.intro.<page>` 键），因此你可以把读过的卡片
一张张收起来，没读过的留着。清除浏览器站点数据会让它们全部回来。

| `/access/tokens` | 令牌 | `token:read` | 给节点和自动化程序用的 API 令牌：权限范围、IP 允许列表、限流、过期时间 | [11-access-control.md](./11-access-control.md) |
| `/access/users` | 用户 | `user:read`（租户级） | 本租户的成员及其角色绑定 | [11-access-control.md](./11-access-control.md) |

| `/admin/tenants` | 租户 | `tenant:manage` 或 `namespace:write` | 租户，以及当前租户内的命名空间 | [11-access-control.md](./11-access-control.md) |

有两个入口需要补充说明：

- **用户**是按租户级检查的，不是按命名空间。只限定在某个命名空间或某些站点上的绑定，无论角色多高都不会授予它。
- **租户**在侧边栏里对 `tenant:manage`（平台管理员）或 `namespace:write`（租户所有者）可见，但页面本身对持有
  `namespace:read` 的人也以只读方式打开。因此一个 viewer 直接用 URL 进入时，能看到列表，但没有创建和删除操作。

## 不同权限的人看到什么

控制台没有「只读模式」开关。你看到什么，完全由你在当前租户和命名空间下的角色绑定决定，而服务端在每个请求上会再校验
一遍同样的规则。

### 只读用户（`viewer` 角色）

命名空间级的 `viewer` 绑定授予 `namespace:read`、`site:read`、`identity:read`、`proxy:read`、`policy:read`、
`breaker:read`、`config:read`、`secret:list`、`dashboard:read`、`audit:read` 和 `notify:read`。实际效果是：

- 侧边栏里**除了「令牌」「用户」「租户」之外**的入口都可见。
- 每个页面都能打开，包括「密钥」——但密钥的值永远不会显示：明文查看需要 `secret:reveal`。
- 会产生变更的按钮都在，但处于禁用状态，气泡提示写着**需要 `<权限>` 权限**。你能看到这个页面能做什么，这正是设计意图。

### 站点受限用户

一个绑定可以被限定到指定站点。这样的用户能看到调度相关的页面，但是：

- 列表由服务端过滤到该绑定覆盖的站点，浏览器端没有任何办法把范围放宽。
- 命名空间级权限**绝不会**由按站点的授权满足。配置中心、密钥、令牌、用户、审计日志和通知依然进不去；代理的写入与
  操作动作也一样，无论站点绑定上挂的是哪个角色。
- `proxy:read` 和 `namespace:read` 是例外：钉在该命名空间上的站点受限绑定确实会授予它们，所以代理池是可读的。

### 平台管理员

在任何租户下都能通过所有权限检查，并且是唯一能持有 `tenant:manage` 和 `kek:manage` 的用户类型。账号菜单里会显示
**平台管理员**标记。没有任何角色绑定的平台管理员依然能进入**租户**和**个人资料**。

### 什么权限都没有的人

已登录但没有任何角色绑定的用户，在除个人资料之外的每个页面上都看到「没有租户访问权限」，并被提示联系租户所有者或
平台管理员。

完整的权限清单、四个角色以及额外权限，见[《租户、用户与令牌》](./11-access-control.md)。

## URL、筛选条件与可分享的链接

页面状态保存在 URL 里。筛选条件、当前标签页、时间范围和展开的行都是查询参数，并且是原地更新的，所以浏览器的后退
按钮走的是你的页面导航，而不是每一次筛选输入：

```text
/identities?site=example-site&states=banned&order_by=score
/breakers?site=example-site&tab=history
/requests?site=example-site&outcomes=captcha,banned&range=6h
```

请求明细和风险事件两个页面上的时间范围是 `range=15m|1h|6h|24h|7d`，或者 `range=custom&from=…&to=…`，边界用
ISO 8601 或毫秒时间戳。`outcomes` 是用逗号分隔的判定结果列表，取值只有这十二个——`success`、`empty`、
`rate_limited`、`captcha`、`auth_invalid`、`forbidden`、`banned`、`proxy_error`、`network_error`、
`target_error`、`client_error`、`unknown`——其他词会被静默丢弃。

这意味着你正在看的任何视图都是一条可以直接粘到故障群里的链接。但有两点要注意：

- **租户和命名空间不在 URL 里**（见[作用域切换器](#作用域切换器)）。
- 对方需要有同样的读权限，否则看到的是「没有权限」。

鼠标悬停在侧边栏入口上时，对应页面就已经开始在后台加载，所以点击是瞬时的；返回列表时滚动位置也会被还原。

## 键盘操作与无障碍

控制台建立在无障碍基础组件之上，不用鼠标也能操作。

| 操作 | 按键 |
| --- | --- |
| 在控件之间移动 | `Tab` / `Shift+Tab` |
| 展开下拉菜单（租户、命名空间、语言、主题、账号、筛选） | `Enter` 或 `Space` |
| 在展开的菜单内移动 | `↑` / `↓`、`Home` / `End`，或直接输入首字母跳转 |
| 选中菜单项 | `Enter` |
| 关闭菜单或对话框 | `Esc` |
| 打开表格行指向的对象 | 在聚焦的行上按 `Enter` 或 `Space` |
| 折叠或展开页面说明卡片 | 在卡片标题上按 `Enter` 或 `Space` |
| 在标签输入框里添加或删除标签 | `Enter` 或 `,` 添加；输入框为空时按 `Backspace` 删掉最后一个 |

其他细节：

- 每个可聚焦元素都有可见的焦点环；对话框内焦点被锁定，关闭后回到触发它的控件。
- 所有纯图标按钮都有无障碍名称——收起侧边栏、语言、主题、账号菜单、刷新、上一页等等——收起状态的侧边栏会把页面名称
  同时作为气泡提示和链接名称暴露出来。
- 实时更新圆点是一个状态元素：颜色从不是唯一的信息载体，状态同时也是它的无障碍名称，并且可以用 `Tab` 聚焦到。
- 侧边栏的名称是「主导航」，面包屑是「面包屑导航」；当前页面那一节会被标记为当前页。
- 表头会把排序方向暴露给读屏软件（`aria-sort`），已选择的行数显示在批量操作条上；被禁用的操作通过气泡提示说明原因，
  而这个提示仅靠键盘聚焦就能看到，不需要鼠标悬停。
- 登录错误出现的瞬间会以警报形式播报。
- 两套主题都按可读对比度设计，页面也声明了自己的配色方案，使浏览器自绘的控件（滚动条、表单控件）保持一致。

控制台没有全局单键快捷键，所以在筛选框里打字永远不会触发页面上别的动作。

## 进入控制台的头十分钟

下面这条路走完，你就能读懂自己这套集群正在发生什么。

1. **登录**，先看右上角：你即将查看的租户和命名空间。不对就先切换。
2. **概览。** 读最上面那六个数字：可用身份、获取 QPS、上报 QPS、成功率、风险率、打开的熔断器。切换统计窗口
   （`1m`、`5m`、`15m`、`1h`）判断某个数字是尖峰还是趋势；这个页面每 10 秒自动刷新一次。
3. **往下翻概览**，看各站点卡片。每张卡片都按状态拆分它的身份数量，并标出低于低水位或有熔断器打开的端点组。
   这里能看出**哪个**站点出了问题。
4. **站点。** 看看你的站点是怎么切分成客户端类型和端点组的。每一次冷却、每一个熔断器、每一条策略绑定都以这套结构
   为作用域，值得花五分钟。见[《核心概念》](./04-concepts.md)。
5. **身份。** 筛选到某一个站点，按健康分排序。打开一个身份，读它的状态时间线：你就明白「调度器把它冷却了」在实际
   数据上长什么样。
6. **冷却热力图。** 选同一个站点和客户端。网格是「身份 × 端点组」，按剩余冷却时间着色。一整列的竖条说明这个端点组
   出了问题；零散的点只是正常轮换。
7. **熔断器。** 看看哪些端点组处于打开状态，并留意：在自动熔断反应过来之前，你可以自己打开一个熔断器，或者直接
   暂停整个站点来止血。
8. **请求明细**或**风险事件。** 把该站点最近一小时的非成功上报筛出来。这就是前面几个页面所展示现象背后的证据。
9. **策略。** 打开绑定到该站点的策略，读一读产生这些冷却的轮换规则和信号规则。先别急着改——先看
   [《策略》](./08-policies.md)。
10. **审计日志。** 确认你自己这次会话出现在里面。你在这里做的每件事都会被记录，包括被拒绝的明文查看尝试。

准备好接入节点时，去**令牌**页面，只授予该节点需要的权限范围签发一个令牌，然后按
[《节点 API 参考》](./13-node-api.md)接入。
