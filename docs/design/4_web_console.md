# Spinneret v0.1 — Web Console Specification

The console is a single-page application in `web/`, built with Vite and embedded into the Go binary
(`web/embed.go`, `//go:embed all:dist`). It talks to the server exclusively through the Connect APIs (JSON) plus one SSE
endpoint. It must be usable by operators daily: fast tables, clear states, safe destructive actions, bilingual UI.

## 1. Stack (fixed)
- React 18 + TypeScript (strict) + Vite 6, package manager **pnpm** (lockfile committed).
- Routing: `@tanstack/react-router` (code-based route tree in `src/router.tsx`, lazy route components).
- Data: `@tanstack/react-query` v5; tables: `@tanstack/react-table` v8 + `@tanstack/react-virtual` v3.
- API: `@connectrpc/connect` v2 + `@connectrpc/connect-web` v2 + `@bufbuild/protobuf` v2; code generated by
  `@bufbuild/protoc-gen-es` v2 into `web/src/gen` via `web/buf.gen.yaml` (`buf generate ../proto --template buf.gen.yaml`),
  script `pnpm gen`. Generated code is committed.
- UI: Tailwind CSS v4 (`@tailwindcss/vite`), shadcn/ui-style components written into `src/components/ui/*` on top of
  Radix primitives (`@radix-ui/react-*`), `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react` icons,
  `sonner` toasts, `cmdk` optional.
- Charts: `echarts` via a thin `src/components/charts/EChart.tsx` wrapper (resize observer, theme aware).
- Editors: `@monaco-editor/react` with **local** `monaco-editor` (no CDN: `loader.config({ monaco })` and Vite worker
  imports) for YAML/JSON/text editing and `DiffEditor` for version diffs.
- i18n: `i18next` + `react-i18next`; languages `en` (default) and `zh-CN`; resources split per feature namespace in
  `src/i18n/locales/<lang>/<feature>.json`; language persisted in localStorage.
- Tests: `vitest` + `@testing-library/react` for units; `@playwright/test` smoke E2E in `web/e2e` against a running stack.
- Lint/format: `eslint` (typescript-eslint, react-hooks) + `prettier`. `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` must pass.

## 3. API usage conventions
- Transport: `createConnectTransport({ baseUrl: window.location.origin, useBinaryFormat: false, interceptors })` with an
  interceptor that sets `X-Spinneret-CSRF: 1` and `X-Spinneret-Tenant: <active tenant id>` on every request and, on
  `Code.Unauthenticated`, clears auth state and navigates to `/login?redirect=…`.
- Session cookies are HttpOnly; the SPA never sees tokens. `AuthService.GetMe` on boot decides the route.
- Every namespace-scoped request passes the active namespace **name**. The active tenant and namespace live in
  `AuthContext`, are persisted to localStorage (`spinneret.tenant`, `spinneret.namespace`) and shown in the topbar.
- Errors: show `ConnectError.rawMessage` plus the `Spinneret-Reason` header (available via `ConnectError.metadata`) mapped to
  a translated message when known.
- Lists: server pagination with `page_size` + `page_token` (cursor stack for back navigation); list refetch every 5 s
  where the page shows live state (identities, proxies, breakers, overview), paused while a dialog is open.
- Real time: `EventSource('/api/v1/events/stream?tenant=<tenant id>&namespace=<ns name>')` (cookie auth); events `breaker.transition`,
  `identity.state`, `proxy.state`, `alert`, `config.published`, `policy.published` → toast (breaker/alert only) and
  query invalidation by key prefix.
- Permissions: `AuthContext.can(permission, siteId?)` computed from `GetMe` (namespace-wide permissions or per-site
  permissions). Hide navigation entries the user cannot read; disable action buttons without permission (tooltip explains).
- Destructive actions (ban, delete, archive, revoke, publish, rollback, reveal) use `ConfirmDialog`; bulk actions show the
  number of affected items; reveal of secrets/payloads requires an explicit confirmation step.

## 4. Pages (routes)
| Route | Page | Main APIs |
| --- | --- | --- |
| `/login` | Login | AuthService.Login |
| `/` | Overview: per-site cards (available identities, acquire/report QPS, success/risk/unknown ratio), trend charts, open breakers, low-watermark warnings, node stats | DashboardService.GetOverview/GetTimeSeries/GetNodeStats |
| `/identities` | Identities: virtualized table, filters (site, type, states, tags, account, region, search, score), bulk cooldown/ban/unban/disable/enable/archive, import dialog (JSONL/CSV upload + dry run + result report) | IdentityAdminService |
| `/identities/$id` | Identity detail: masked payload (reveal), per-endpoint hot state (score, cooldown, reuse, availability), bound proxy, state timeline, recent risk events, payload update, manual operations | IdentityAdminService, DashboardService.ListRiskEvents |
| `/identity-types` | Identity types: list, YAML editor with schema errors, delivery preview (sample payload → Acquire credential) | IdentityAdminService |
| `/accounts` | Accounts: list, upsert, ban/unban/cooldown | IdentityAdminService |
| `/proxies` | Proxies: table with health, per-site cooldown/score, import (lines/JSONL/CSV), bulk operations, check now, provider stats tab | ProxyAdminService |
| `/sites` | Sites & endpoint groups: site CRUD, clients, pause switch, endpoint groups with URI rules editor (drag order for regex), URI tester showing matched group + resolved policies | SiteAdminService, BreakerAdminService.SetSitePaused |
| `/policies` | Policies: list by kind, editor (form mode for rotation/breaker, rule-list mode for signal/action, YAML mode for all), draft/publish/rollback, version diff, bindings manager, rule debugger (paste a report → outcome, blame, planned actions) | PolicyAdminService |
| `/heatmap` | Cooldown heatmap: identities × endpoint groups, metric cooldown remaining or score, drill-down to identity | DashboardService.GetHeatmap |
| `/breakers` | Breakers: per endpoint group state, window metrics, probe metrics, history, manual open (duration/indefinite) / close, site switches | BreakerAdminService |
| `/config` | Config center: group/key tree, Monaco editor with schema validation, draft/publish, versions, diff, rollback | ConfigAdminService |
| `/secrets` | Secrets: path tree, versions, masked values, reveal (confirmation), access logs, KEK status + rewrap (platform admin) | SecretAdminService |
| `/requests` | Request explorer (ClickHouse): filters, table, latency/outcome breakdown; disabled state when ClickHouse is off | DashboardService.QueryRequestEvents |
| `/risk-events` | Risk events (PostgreSQL) list with filters | DashboardService.ListRiskEvents |
| `/notifications` | Channels CRUD + test + alert history | NotificationAdminService |
| `/access/tokens` | Node tokens: create (scopes builder, IP allowlist, expiry; plaintext shown once), revoke | AccessAdminService |
| `/access/users` | Users & role bindings (namespace + site restrictions, extra permissions), reset password | AccessAdminService |
| `/access/audit` | Audit log search | AccessAdminService.ListAuditLogs |
| `/admin/tenants` | Tenants & namespaces (platform admin / owners) | TenantAdminService |
| `/settings/profile` | Profile: language, change password | AuthService.ChangePassword |

## 5. Visual design
- Dense, calm operator UI: neutral slate palette, one accent (indigo), semantic colors for states:
  active=emerald, pending=sky, expired=amber, banned=rose, quarantined=orange, disabled=zinc, retired=stone,
  breaker closed=emerald, half_open=amber, open=rose. Light and dark themes (class strategy, follows system by default).
- Sidebar groups: Overview · Scheduling (Identities, Identity Types, Accounts, Proxies, Sites, Policies, Heatmap, Breakers) ·
  Configuration (Config Center, Secrets) · Observability (Requests, Risk Events, Notifications) · Access (Tokens, Users,
  Audit) · Platform (Tenants).
- Tables: sticky header, monospaced IDs with copy button, relative times with absolute tooltip, row click opens detail.
- Every page handles loading (skeleton), empty, error (retry) and permission-denied states.
- Responsive down to 1280 px wide desktop; mobile is not a target but must not break.
